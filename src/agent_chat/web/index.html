    GET STARTED

    Set up Agent chat

    Agent chat is a local browser room for talking to already-connected agents. A bridge is the local program that connects this room to Codex. Finish this guide when the bridge is connected and a message to a visible agent appears in the feed.

    1. Install the tools in the Agent chat checkoutOn the machine where you will run agents, install Python 3.10+ and jq with that machine’s supported package manager. If Homebrew is already installed on macOS, brew install python jq does that; on Debian/Ubuntu use sudo apt-get install python3 python3-venv python3-pip jq procps. Then open a terminal in your Agent chat checkout: cd /absolute/path/to/agent-chat chooses that folder; python3 -m venv .venv creates an isolated Python environment; . .venv/bin/activate selects it for this terminal; python -m pip install . installs Agent chat; and agent-chat-client --help confirms the client is ready. Keep this terminal open for the next steps.
    2. Onboard Codex before connecting a bridgeStart with OpenAI’s Codex onboarding. For newcomers, it directs macOS and Windows users to the ChatGPT desktop app and the Codex quickstart: sign in, choose a project, and send a first message. A signed-in Codex session with that first response in the chosen project is the success indicator. Codex handles its own authentication; Agent chat does not select providers or models and never stores Codex credentials in this browser or local storage. Continue only after Codex can open that local session.
    3. Start the local chat server and open the browserOn the machine that stores shared chat data, run agent-chat-server --db /absolute/path/to/state.sqlite3. This starts the browser room and HTTP API; the default local address is http://127.0.0.1:8765. Open that address in a browser, sign in as operator, and use the privately supplied Agent chat API token as the password. A loaded room is success; leave the server terminal running and configure the workspace connection next.
    4. Configure and start the workspace bridgeIn the activated checkout terminal on the workspace machine, set Agent chat’s connection variables: export AGENT_CHAT_SERVER=http://127.0.0.1:8765, export AGENT_CHAT_API_TOKEN=YOUR_PRIVATE_TOKEN, export AGENT_CHAT_PROJECT=default, export AGENT_CHAT_ROOT=/absolute/path/to/your-project, then unset AGENT_CHAT_DB. Replace only the non-secret placeholder with the token provided privately; these variables authenticate Agent chat and do not sign in to a model provider. Run agent-chat-client doctor --bridge to check the connection, then agent-chat-client bridge to start it. Continue when it prints ready and the sidebar says the wake bridge is connected.
    5. Understand and prepare the neutral rootA neutral root is a dedicated folder outside project workspaces. Root is the one Codex conversation that coordinates project teams. AGENTS.md is the instruction file that an agent reads in its workspace. In the neutral-root folder, run agent-chat-root-guidance --workspace /absolute/neutral-root --install; it creates a baseline only when AGENTS.md is absent and preserves an existing developer file. This install does not start, create, or enroll any agent. An authorized administrator must prepare and enroll root or another agent before messaging. If no connected agent is visible in the sidebar, stop here and ask that administrator for help; do not try to create one from this guide.
    6. Optional: change an existing agent’s model or reasoningThis is administration, not normal setup, and it is separate from Codex authentication. Only an authorized owner of an existing main agent should use the named bounded workflow in docs/agents.md, “Change a main agent’s model on the same thread,” after the agent is idle with no active turn, queued input, or open guard. That workflow supplies the complete exact agent, bound thread, requested model, reasoning effort, and request-ID sequence plus its status readback. Leave this step for the existing agent owner; it is not part of first-time authentication or messaging.
    7. Verify the connection and send a messageOnce an administrator has made a connected agent visible, select it in the sidebar and check its current settings. Send a short message; success is that the message appears in the feed while the bridge remains connected. Use @agent only to choose recipients, replies keep their recipients, and Attach stays beside Send.
